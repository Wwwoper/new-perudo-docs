# S3 — Подсчёт кубиков: полный контракт

Версия: 1.0
Статус: согласованная спецификация S3.1–S3.4.

## 1. Назначение и границы

S3 учит количественно считать совпадения для выбранной ставки и определять, сколько совпадений требуется на скрытых кубиках.

S2 отвечает за считывание данных со стола. S3 выполняет подсчёт. S4 рассчитывает вероятность на основе результата S3. S8 принимает игровое решение.

S3 не рассчитывает вероятность и не принимает решение о безопасности ставки.

## 2. Правила подсчёта

В обычном режиме (`NORMAL`):

- для ставки на грань 2–6 совпадения равны `count(face) + count(1)`;
- для ставки на единицы совпадения равны `count(1)`.

В режиме `PALIFICO` единицы не являются джокерами: совпадения равны только `count(face)` для выбранной грани.

Подсчёт должен учитывать `round_mode`, `ruleset_id` и `ruleset_version`. Активные кубики участвуют в расчёте; выбывшие участники остаются видимыми, но не участвуют в расчётах.

## 3. Входные модели

```python
@dataclass(frozen=True)
class PlayerDice:
    player_id: str
    dice_count: int

@dataclass(frozen=True)
class Bid:
    quantity: int
    face: int

@dataclass(frozen=True)
class GameSituation:
    players: tuple[PlayerDice, ...]
    current_player_id: str
    own_dice: tuple[int, ...]
    bid: Bid
```

`Ruleset` содержит `ruleset_id`, `version`, `ones_are_wildcards`. Для согласованного классического профиля используется `PERUDO_ZYGOMATIC_CLASSIC_V1`; фактический режим раунда задаётся отдельно.

`CountContext` передаёт `round_mode`, `ruleset_id` и `ruleset_version`.

`CountResult` содержит:

- `own_matches`;
- `own_dice_count`;
- `total_dice_count`;
- `hidden_dice_count`;
- `required_matches`;
- `is_requirement_already_met`;
- `round_mode`;
- `ruleset_id`;
- `ruleset_version`.

`required_matches` — количество совпадений, которое необходимо получить на скрытых кубиках. Это не общее количество совпадений по столу.

## 4. Математическое ядро

Логические функции:

- `validate_dice` — проверка значений кубиков;
- `count_face_matches` — подсчёт точной грани с учётом переданного режима;
- `count_bid_matches` — подсчёт совпадений для ставки;
- `count_total_dice` — общее количество активных кубиков;
- `count_hidden_dice` — количество кубиков, значения которых неизвестны игроку;
- `required_matches` — недостающее число совпадений;
- `calculate_full_count` — формирование полного `CountResult`.

Для собственного набора кубиков `own_matches` определяется по правилам текущего режима. Количество требуемых совпадений на скрытых кубиках:

`required_matches = max(0, bid.quantity - own_matches)`.

Если собственных совпадений достаточно, `required_matches = 0` и `is_requirement_already_met = True`.

S3 не получает и не передаёт скрытые значения кубиков соперников. Он работает только с количеством скрытых кубиков.

## 5. Поднавыки

### S3.1 — Подсчёт собственных совпадений без джокеров

Вводный этап: подсчитать количество кубиков заданной грани в собственном наборе. Он формирует базовую точность счёта до введения джокеров.

### S3.2 — Учёт единиц-джокеров

Типы упражнений:

- обычная ставка на грани 2–6;
- ставка на единицы;
- сравнение подсчёта с учётом и без учёта единиц;
- поиск ошибки в подсчёте;
- смешанные комбинации;
- смена значения ставки.

Уровни L1–L5. Предварительный критерий: минимум 12 упражнений, около 90% правильности; порог калибруется.

Коды ошибок:

- `S3_WILDCARD_OMITTED`;
- `S3_WILDCARD_EXTRA`;
- `S3_FACE_CONFUSION`;
- `S3_COUNT_MISS`;
- `S3_COUNT_DUPLICATE`;
- `S3_BID_RULE_CONFUSION`.

### S3.3 — Сколько совпадений ещё нужно

Рассчитать недостающее количество совпадений:

`R = max(0, bid_quantity - own_matches)`.

Коды ошибок:

- `S3_OWN_DICE_IGNORED`;
- `S3_REMAINING_NEGATIVE`;
- `S3_REMAINING_CALC_ERROR`.

### S3.4 — Полный подсчёт

Ученик последовательно определяет:

1. общее количество активных кубиков;
2. количество скрытых кубиков;
3. собственные совпадения;
4. необходимое количество совпадений на скрытых кубиках.

Модель поддерживает разное количество кубиков у участников. Промежуточные поля проверяются отдельно. Правильный итог при неверных промежуточных ответах не засчитывается полностью.

## 6. Контракты упражнения и ответа

Используются общие контракты `SkillId`, `Exercise`, `ExerciseConfig`, `ExerciseAnswer`, `AnswerMode`, `FieldResult`, `EvaluationResult`.

Генераторы S3 реализуют общий `ExerciseGenerator` Protocol. Для воспроизводимости сохраняются seed, идентификатор/версия генератора, конфигурация, ruleset id/version и готовый экземпляр упражнения.

Ответы могут быть выбором или самостоятельным числовым вводом. Составные ответы проверяются по отдельным полям.

## 7. Диагностика

Диагностика различает первичную ошибку и зависимые от неё ошибки. Например, неверно определённое число собственных совпадений может объяснять последующую ошибку в `required_matches`; эти ошибки не должны безусловно считаться независимыми.

Коды ошибок должны сохраняться структурированно, а пользовательский текст формируется отдельным Feedback компонентом.

## 8. Прогресс

Состояния навыка: `NOT_STARTED`, `LEARNING`, `PRACTICING`, `MASTERED`, `NEEDS_REVIEW`.

Порог S3 предварительно около 90% при минимуме 12 упражнений. Для подтверждения освоения нужны разные типы упражнений и устойчивость результата; окончательные значения калибруются.

## 9. Тестирование

Unit:

- подсчёт каждой грани;
- учёт единиц в NORMAL;
- отсутствие джокеров в PALIFICO;
- ставка на единицы;
- нулевое требование;
- разные количества кубиков;
- валидация значений кубиков;
- пропуск совпадения и двойной подсчёт;
- границы `required_matches`.

Property-based:

- `required_matches` никогда не отрицателен;
- `own_matches` не превышает количество собственных кубиков;
- `hidden_dice_count` неотрицателен;
- подсчёт детерминирован для одинаковых входов;
- скрытые значения не требуются для вычисления `CountResult`.

Integration:

- генерация → публичное представление → ответ → проверка;
- корректная передача `CountResult` в S4;
- версия правил и режим раунда сохраняются;
- повторная отправка не искажает метрики попыток.
