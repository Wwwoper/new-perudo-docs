# S4 — Вероятность и оценка риска: полный контракт

Версия: 1.0
Статус: согласованная спецификация S4.1–S4.5.

## 1. Назначение и границы

S4 учит рассчитывать и интерпретировать вероятность совпадений для заданной ставки.

- S3 считает собственные совпадения и недостающие совпадения.
- S4 рассчитывает вероятность на скрытых кубиках и помогает интерпретировать математический результат.
- S8 принимает решение о ставке или вызове.

S4 не выбирает ставку, не рекомендует объявлять Dudo и не оценивает стратегию соперника.

## 2. Вероятность одного скрытого кубика

Для классического профиля:

| Режим | Ставка | Вероятность совпадения на одном скрытом кубике |
|---|---|---:|
| NORMAL | грань 2–6 | 1/3 |
| NORMAL | единица | 1/6 |
| PALIFICO | грань 1–6 | 1/6 |

В NORMAL единицы являются джокерами для ставок на 2–6. Для ставки на единицы совпадают только единицы. В PALIFICO джокеров нет.

Точные значения внутри математического ядра представлены `Fraction`; проценты используются только для отображения.

## 3. Точные математические модели

Для события на одном скрытом кубике используется вероятность `p` из правил выше.

Для `n` независимых скрытых кубиков число совпадений:

`X ~ Binomial(n, p)`.

Вероятность ровно `k` совпадений:

`P(X = k) = C(n, k) * p**k * (1-p)**(n-k)`.

Вероятность не менее `k` совпадений:

`P(X >= k) = sum(P(X = i), i=k..n)`.

Вероятность хотя бы одного совпадения:

`P(X >= 1) = 1 - (1-p)**n`.

Если собственных совпадений `m`, количество по ставке `q`, то требуемое число совпадений на скрытых кубиках:

`r = max(0, q - m)`.

Если `r = 0`, вероятность выполнения требования равна 100%. Если `r > n`, вероятность равна 0%.

S4 получает необходимые параметры из `CountResult` и не пересчитывает собственные совпадения.

## 4. Математическое ядро и контракты

Основные структуры:

- `ProbabilityEvent` — событие, вероятность которого рассчитывается;
- `ProbabilityRepresentation` — точное и отображаемое представление вероятности;
- `ProbabilityQuestion` / `ProbabilityAnswer` / `ProbabilityEvaluation`;
- `BinomialProbabilityInput` / `BinomialProbabilityResult`;
- `ProbabilityExerciseData`;
- `ProbabilityEstimationQuestion`;
- `EstimationTarget` / `EstimationAnswer` / `EstimationEvaluation`.

`ProbabilityEvent` должен включать `round_mode`, `ruleset_id`, `ruleset_version`. Версия правил влияет на значение `p`.

Все точные вычисления выполняются через рациональные значения. Преобразование в проценты и округление — слой представления.

## 5. Граничные случаи биномиального распределения

Обработать явно:

- `n < 0` — некорректный вход;
- `k < 0` — вероятность не менее отрицательного числа совпадений равна 1, если функция поддерживает такую семантику; для точного события отрицательное k даёт 0;
- `n = 0` — распределение сосредоточено на нуле;
- `k = 0` — `P(X >= 0) = 1`;
- `k > n` — `P(X >= k) = 0`;
- `p = 0` и `p = 1` — граничные распределения;
- сумма всех вероятностей полного распределения равна 1.

API должно различать вероятность точного события `P(X=k)` и хвостовую вероятность `P(X>=k)`.

## 6. S4.1 — Вероятность одного совпадения

Обучение идёт от интуиции и примеров к формальному биномиальному объяснению.

Вероятность показывается в процентах, дробях и визуальной шкале/модели. Формулы раскрываются постепенно.

Точный расчёт отделён от приблизительной оценки без калькулятора. Собственные кубики учитываются через результат S3; вероятность рассчитывается только для скрытых кубиков.

Вероятность выполнения требования ставки отделена от вероятности проигрыша и от выбора решения.

Форматы: `SINGLE_CHOICE`, `NUMERIC_INPUT`, `FRACTION_INPUT`, `MATCHING`, `MULTI_SELECT`, `ERROR_IDENTIFICATION`, `EXPLANATION_CHOICE`.

## 7. S4.2 — Вероятность нескольких совпадений

Полное биномиальное распределение вводится постепенно, на L4–L5. До этого используются отдельные вероятности и визуальные подсказки.

Промежуточные вычисления проверяются отдельно на L3–L5. На L1–L2 используются выбор ответа и визуальные подсказки.

Игровые ситуации с собственными кубиками включены в S4.2.4: собственные совпадения и необходимое количество скрытых совпадений берутся из S3.

Типы:

- S4.2.1 — хотя бы одно совпадение;
- S4.2.2 — ровно заданное количество;
- S4.2.3 — не менее заданного количества;
- S4.2.4 — выполнение требования ставки в игровой ситуации.

Форматы: `SINGLE_CHOICE`, `NUMERIC_INPUT`, `FRACTION_INPUT`, `FORMULA_SELECTION`, `STEP_BY_STEP`, `ERROR_IDENTIFICATION`, `COMPARISON`.

## 8. S4.3 — Оценка вероятности без калькулятора

Форматы ответа:

- диапазон вероятности;
- приблизительное числовое значение;
- направление изменения вероятности.

Для диапазона эталонное значение должно попадать внутрь диапазона. Для числового ввода используется централизованный допуск. Для очень малых вероятностей применяется абсолютная погрешность.

На L1–L3 используется визуализация распределения с постепенным уменьшением подсказок. На L4–L5 оценка выполняется самостоятельно.

Типы:

- S4.3.1 — знакомые вероятности;
- S4.3.2 — влияние количества кубиков;
- S4.3.3 — оценка необходимого количества совпадений;
- S4.3.4 — оценка изменения вероятности.

Числовые допуски и конкретные границы диапазонов остаются параметрами для калибровки, не фиксируются этим контрактом как окончательные.

## 9. S4.4 — Сравнение рисков

Сравнивается математическая вероятность событий, а не качество игрового решения.

Количество сравниваемых событий:

- L1–L2: два;
- L3–L4: два или три;
- L5: до четырёх.

Обязательно включать равные вероятности, в том числе при разных игровых условиях. Сравнение выполняется по точным значениям, а не по округлённым процентам.

Результат сравнения: `LESS`, `GREATER`, `EQUAL`.

Выбор события и объяснение оцениваются отдельно. Правильный выбор при неверном объяснении даёт частичный результат.

Типы:

- S4.4.1 — один кубик;
- S4.4.2 — несколько кубиков;
- S4.4.3 — игровые ситуации;
- S4.4.4 — объяснение разницы вероятностей.

Форматы: `SINGLE_CHOICE`, `ORDERING`, `NUMERIC_COMPARISON`, `EQUALITY_IDENTIFICATION`, `ERROR_IDENTIFICATION`, `EXPLANATION_CHOICE`, `STEP_BY_STEP`.

## 10. S4.5 — Интерпретация вероятности

Включается сравнение теоретической вероятности с фактической частотой в серии повторений. Вероятность 1/3 не означает ровно один успех в каждой серии из трёх попыток.

Для классификации утверждений используются:

- `CORRECT`;
- `INCORRECT`;
- `NOT_SUPPORTED`.

Допускаются игровые ситуации Perudo, но пользователь не выбирает ставку и не решает, следует ли оспаривать её.

Типы:

- S4.5.1 — интерпретация числовой вероятности;
- S4.5.2 — вероятность и гарантия;
- S4.5.3 — вероятность и фактический результат;
- S4.5.4 — корректность выводов.

## 11. Диагностика ошибок

Диагностика должна различать математическую ошибку, ошибку чтения входных данных, ошибку интерпретации и неподдержанное заключение.

Основные коды:

- `S4_PROBABILITY_MEANING_ERROR`;
- `S4_PROBABILITY_AS_GUARANTEE`;
- `S4_LOW_PROBABILITY_AS_IMPOSSIBLE`;
- `S4_HIGH_PROBABILITY_AS_CERTAINTY`;
- `S4_OUTCOME_PROBABILITY_CONFUSION`;
- `S4_SINGLE_OUTCOME_GENERALIZATION`;
- `S4_PROBABILITY_FREQUENCY_CONFUSION`;
- `S4_UNSUPPORTED_CONCLUSION`;
- `S4_MODEL_SCOPE_IGNORED`;
- `S4_ESTIMATION_RANGE_ERROR`;
- `S4_ESTIMATION_TOO_HIGH`;
- `S4_ESTIMATION_TOO_LOW`;
- `S4_ESTIMATION_PRECISION_ERROR`;
- `S4_LINEAR_PROBABILITY_ASSUMPTION`;
- `S4_DICE_COUNT_IMPACT_MISSED`;
- `S4_REQUIRED_MATCHES_IMPACT_MISSED`;
- `S4_PROBABILITY_DIRECTION_ERROR`;
- `S4_MULTIPLE_CHANGES_CONFUSION`.

Также диагностируются ошибки грани, джокеров, ставки на единицы, дробей, процентов, округления, биномиального коэффициента, степеней, суммирования, дополнения и смешения exact/at-least.

## 12. Допуски и прогресс

Эквивалентные дроби, десятичные числа и проценты могут приниматься как эквивалентные ответы с небольшим централизованным допуском. Внутренние вычисления остаются точными.

Предварительный порог освоения: минимум 12 попыток и 85–90% правильности. Порог требует калибровки; самостоятельность, разнообразие типов и устойчивость результата также учитываются.

## 13. Тестирование

Unit:

- точные дроби для `p`;
- биномиальные вероятности;
- `n=0`, `k=0`, `k>n`;
- `p=0`, `p=1`;
- вероятность 0% и 100%;
- сумма полного распределения равна 1;
- сравнение точных вероятностей и равенство;
- допуски и округление;
- интерпретация вероятности и частоты.

Property-based:

- все вероятности находятся в диапазоне [0, 1];
- сумма распределения равна единице;
- хвостовая вероятность не возрастает при увеличении k;
- при фиксированных n и p результаты детерминированы.

Integration:

- `CountResult` S3 корректно преобразуется во вход S4;
- режим Palifico влияет на p;
- версии правил сохраняются;
- S4 не пересчитывает собственные совпадения и не формирует игровую рекомендацию.

## 14. Открытые параметры
