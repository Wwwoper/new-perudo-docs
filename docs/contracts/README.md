# Контракты предметной области и навыков

Этот каталог содержит нормативные контракты. При расхождении приоритет определяется так:

1. `game-domain.md` — игровые правила и состояние;
2. контракт соответствующего навыка — учебная ответственность, входы/выходы и оценивание;
3. `learning-core.md` — общий жизненный цикл упражнения и попытки;
4. каталог упражнений и примеры — конкретные сценарии, не источник новых правил;
5. review/handoff документы — статус проверки, но не замена нормативному контракту.

## Карта контрактов

| Навык/область | Документ | Ответственность |
|---|---|---|
| Game Domain | `game-domain.md` | Правила, состояние, события, ставки и раунды |
| S1 | `s1-rules-and-mechanics.md` | Понимание и применение правил |
| S2 | `s2-perception.md` | Считывание состояния стола |
| S3 | `s3-counting.md` | Количественный подсчёт |
| S4 | `s4-probability.md` | Точная вероятность и риск |
| S5 | `s5-bid-mechanics.md` | Проверка переходов и допустимости ставок |
| S6 | `s6-bid-history.md` | Чтение публичной истории торгов |
| S7 | `s7-opponent-analysis.md` | Анализ наблюдений с учётом неопределённости |
| S8 | `s8-decision-making.md` | Качество решения в момент выбора |
| S9 | `s9-match-strategy.md` | Условный долгосрочный план партии |
| Learning Core | `learning-core.md` | Общие модели упражнения, ответа и попытки |

## Общие требования

- Все игровые сценарии фиксируют `ruleset_id` и `ruleset_version`.
- Навык-владелец один; вторичные навыки дают evidence только по независимым критериям.
- Ошибка вспомогательного навыка не должна автоматически ухудшать оценку целевого навыка.
- Публичные данные не содержат закрытые значения кубиков.
- Контракты не утверждают, что реализационные тесты выполнены.
- Изменение нормативного Game Domain требует versioning, impact review и обновления тест-векторов.
