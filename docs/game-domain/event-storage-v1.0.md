# Event Storage Contract

Версия: 1.0.

## Хранение

Логические компоненты: `GameRecord`, `EventLog`, `PrivateEventData`, `CurrentGameState`, `StateSnapshots`.

`DomainEvent` содержит event_id, game_id, round_id, event_type, sequence_number, occurred_at, actor_id, payload, ruleset_id/version и schema_version. Закрытые значения бросков хранятся отдельно и связываются с соответствующим событием.

## Атомарность и идемпотентность

Каждая изменяющая состояние команда имеет обязательный `command_id`. События команды и новое состояние сохраняются одной транзакцией. Повтор того же ID с тем же payload возвращает прежний результат без новых событий; тот же ID с другим payload — конфликт.

## Снимки и восстановление

Снимки создаются после каждого раунда и завершения партии. Snapshot неизменяем и содержит позицию последнего события, версии правил и схемы, состояние.

Восстановление выполняется от последнего целостного snapshot и событий после него по непрерывному sequence. Если последний snapshot повреждён, допускается переход к предыдущему целостному snapshot при условии целостности журнала, доступности миграторов и прохождения итоговых инвариантов. Если все снимки повреждены, но журнал целостен и поддерживается, восстановление возможно с начала.

Повреждённый журнал, неизвестный `event_type`, неизвестная версия payload или отсутствие необходимого мигратора останавливают восстановление с явной ошибкой.

## Версии

Независимо версионируются правила, схема событий, схема снимков и генераторы. Старые события не переписываются; изменения форматов выполняются явными миграторами.

Партии хранятся до явного удаления пользователем. Физическая БД, резервное копирование и синхронизация пока не выбраны.
