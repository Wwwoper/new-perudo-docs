# Perudo — целевая платформа и модель распространения

Версия: 1.0
Статус: принятое продуктовое решение для MVP.

## 1. Принятое решение

Целевая платформа первого релиза — адаптивное web-приложение для desktop и mobile.

Модель распространения:

- приложение открывается по HTTPS URL в современном браузере;
- интерфейс адаптируется к широким и узким экранам, без отдельных desktop/mobile приложений;
- приложение проектируется как installable PWA там, где браузер и ОС поддерживают установку;
- основной сценарий не требует регистрации, учётной записи или сетевого backend;
- пользовательские данные принадлежат одному локальному профилю в одном browser profile на одном устройстве;
- облачная синхронизация, совместное использование профиля и сетевой multiplayer не входят в MVP.

PWA-installability — способ удобного запуска, а не обещание одинаковых возможностей установки во всех браузерах. Обычный запуск через вкладку браузера остаётся полноценным поддерживаемым сценарием.

## 2. Поддерживаемые режимы

| Режим | Требование MVP |
|---|---|
| Desktop browser | Полный функционал, клавиатура и мышь, адаптация под широкий экран |
| Mobile browser | Полный основной функционал, touch-first управление, вертикальная компоновка |
| Installed PWA | Тот же web-клиент и тот же локальный профиль в рамках того же browser storage partition |
| Offline после первого успешного открытия | Доступ к оболочке приложения и локальным данным; сетевые внешние ресурсы не должны быть обязательны для основного учебного сценария |
| Другой браузер или устройство | Считается отдельным хранилищем; перенос выполняется явным export/import |

Не обещать автоматический перенос данных между браузерами, приватными окнами, профилями ОС или устройствами.

## 3. Границы MVP

В MVP не входят:

- native desktop/mobile приложения и отдельные codebase;
- обязательный backend для игровых и учебных операций;
- регистрация, авторизация и серверный профиль;
- cloud backup и синхронизация;
- multiplayer по сети, социальные функции и рейтинги;
- удалённая проверка ответов.

Статический web hosting может использоваться для доставки HTML/CSS/JS и версий приложения. Это не означает наличие серверной пользовательской сессии или хранение пользовательских данных на сервере.

## 4. Архитектурные последствия

1. Presentation реализуется как responsive web UI, но доменные модули не зависят от DOM, браузерных API или конкретной UI-библиотеки.
2. Application вызывает доменные модули через согласованные порты; в MVP это локальные вызовы в одном runtime.
3. Инфраструктурный адаптер browser storage реализует порты сохранения. Доменные сущности не обращаются к IndexedDB напрямую.
4. Локальная проверка остаётся `TRUSTED_LOCAL`. Она обеспечивает рабочий учебный сценарий, но не защищает эталон от пользователя, контролирующего браузер и устройство.
5. Экспорт/импорт — обязательная часть пользовательского сценария сохранности данных до публичного релиза.
6. Отсутствие backend означает отсутствие серверной синхронизации, серверной авторитетности и централизованного восстановления.

## 5. Прогрессивное улучшение и доступность

- Основные действия доступны с клавиатуры и touch.
- Ключевые сценарии не зависят от hover.
- Макет не должен требовать горизонтальной прокрутки на типовых мобильных ширинах.
- Идентичность игрока и смысловые идентификаторы зон не зависят от экранной позиции.
- Состояния загрузки, ошибки, сохранения и offline представлены текстом/семантикой, а не только цветом.
- Установка PWA не является условием прохождения обучения.

## 6. Критерии приёмки платформы

- PS-01–PS-09 проходят на desktop browser и mobile browser.
- После перезагрузки страницы подтверждённый прогресс и партия доступны в том же browser profile.
- После первого успешного открытия приложение может выполнить основной локальный учебный сценарий без сети.
- Потеря browser storage не маскируется под успешное сохранение; пользователь получает понятное сообщение и рекомендацию создать backup.
- Export на одном устройстве и import на другом восстанавливают профиль в пределах поддерживаемой версии формата.
- Клавиатурный и touch сценарии проверены отдельно.

## 7. Отложенные решения

Следующие решения не блокируют MVP platform decision и принимаются при появлении подтверждённой потребности:

- backend и учётные записи;
- синхронизация между устройствами;
- серверная проверка и недоверенный клиент;
- native wrappers;
- multi-profile на одном устройстве;
- аналитика и телеметрия.

Любое добавление backend должно сопровождаться пересмотром trust model, privacy review, API contracts и политики хранения данных.
