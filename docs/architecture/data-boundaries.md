# Perudo — границы данных, приватность и жизненный цикл артефактов

Версия: 1.0
Статус: проектный контракт безопасности данных.

## 1. Цель

Документ определяет, какие данные существуют, кто может их видеть, когда они раскрываются и какие данные нельзя помещать в DTO, логи или feedback. Это логический контракт; конкретные механизмы авторизации и хранения будут выбраны отдельно.

## 2. Классы данных

| Класс | Примеры | Доступ |
|---|---|---|
| Public game data | Ставка, очередь, число кубиков, разрешённые зоны стола | Представление конкретного игрока/упражнения |
| Private game data | Фактические значения кубиков соперников до раскрытия | Только Game Domain и доверенные игровые операции |
| Own private data | Значения собственных кубиков | Владелец игрока и доверенные операции |
| Public exercise data | Условие, вопрос, варианты, разрешённая ситуация | Клиент ученика |
| Private exercise data | Эталон, генераторный контекст, скрытое состояние synthetic scenario | Exercise Engine / Evaluation |
| Learning records | Отправки, результаты, подсказки, метрики и прогресс | Владелец учебного профиля и учебные сценарии |
| Operational metadata | IDs, версии, timestamps, command IDs, error codes | Внутренние компоненты с минимально необходимым доступом |

## 3. Разделение игровых данных

`GameState` является полной моделью и не сериализуется напрямую в клиентский ответ.

`PlayerGameView` формируется для конкретного игрока и включает только разрешённые ему значения.

`ExerciseGameView` формируется из специально подготовленной ситуации и включает только те факты, которые должны быть видны в конкретном упражнении.

Закрытые значения чужих кубиков до `DICE_REVEALED`:

- не передаются в UI;
- не попадают в `TableView`, `CountContext`, публичные события или ответы API;
- не включаются в тексты ошибок, feedback и логи;
- не должны быть доступны через сериализуемые скрытые поля.

S3 получает собственные значения и количества чужих активных кубиков, а не сами значения чужих граней. S4 получает `CountResult`, а не исходные кубики.

## 4. Разделение данных упражнения

Каждый сохранённый экземпляр логически состоит из:

- `PublicExercise` — условие, видимые данные, вопросы и доступные форматы ответа;
- `PrivateExerciseData` — эталон, закрытый контекст, evaluation criteria и сведения, необходимые для проверки.

Клиент не должен получать `PrivateExerciseData`, даже если UI визуально скрывает эти поля. Исключается передача эталона в DOM/state, preload payload, локальные логи и клиентский кэш.

Проверка выполняется по `exercise_id`/`exercise_version` на доверенной стороне. Ответ клиента содержит только типизированный пользовательский ввод и идентификаторы операции.

Если первый этап использует локальную проверку, граница доверия ограничена локальным приложением; это не считается защищённой серверной проверкой. Контракт должен позволять вынести Evaluation на сервер без изменения формы `PublicExercise` и `AnswerSubmission`.

## 5. Момент раскрытия

- Во время упражнения показываются условие и feedback по основной ошибке.
- До завершения упражнения полный эталон не раскрывается.
- Исправление ответа доступно только после получения feedback.
- После завершения всего упражнения эталон может быть показан в рамках итогового разбора.
- `DICE_REVEALED` в реальной партии — отдельное доменное событие с правилами доступа; оно не должно трактоваться как разрешение на раскрытие в других контекстах/игрокам задним числом без соответствующей политики представления.

## 6. Логи, ошибки и диагностика

Допустимо логировать:

- operation_id / command_id / submission_id;
- game_id / exercise_id / attempt_id;
- версии схемы, правил, генератора и evaluator;
- тип операции, длительность, итоговый статус;
- безопасные error codes.

Запрещено логировать:

- закрытые значения кубиков соперников до раскрытия;
- private exercise expected answers;
- полный private payload;
- пользовательские данные, не требуемые для диагностики.

Ошибки должны быть полезны разработчику, но не раскрывать секретные значения клиенту. Технический traceback остаётся внутренним.

## 7. Сохранение и удаление

Партии сохраняются до явного удаления пользователем — согласованное правило хранения для Game Domain.

Для учебных записей и персональных данных срок хранения, экспорт, удаление и резервное копирование остаются открытыми решениями. До выбора политики нельзя обещать конкретный срок хранения.

Удаление должно учитывать связанные сущности и историю; сброс навыка не удаляет историю прогресса. Сброс SkillProgress — отдельная операция, не эквивалентная удалению пользовательских данных.

## 8. Версионные ссылки и воспроизводимость

Для воспроизводимости проверки и аудита сохраняются применимые идентификаторы:

- ruleset id/version;
- schema version;
- generator id/version и seed;
- exercise id/version;
- evaluator version;
- feedback version, если нужна точная воспроизводимость текста.

Сохранённый экземпляр упражнения остаётся источником истины для проверки старой попытки. Нельзя регенерировать его текущей версией генератора.

## 9. Проверяемые security-инварианты

1. В клиентском игровом DTO отсутствуют закрытые значения соперников.
2. В клиентском exercise DTO отсутствуют expected answers и private criteria.
3. Ошибка Evaluation не раскрывает expected answer до завершения упражнения.
4. Логи не содержат private dice/exercise payload.
5. S3 и S4 получают только минимально необходимые данные.
6. Выбывшие участники не участвуют в расчётах, хотя остаются видимыми.
7. Feedback строится только из разрешённого контекста.
8. Проверка старого упражнения использует сохранённую версию критериев.
9. Публичное событие не раскрывает приватный payload, даже если хранится рядом с ним.

## 10. Минимальные тесты

- Snapshot/API serialization tests для GameState → PlayerGameView.
- Snapshot/API serialization tests для Exercise → PublicExercise.
- Negative tests: попытка получить private payload из UI/use-case.
- Log capture tests на отсутствие секретных значений.
- Tests на feedback до/после завершения упражнения.
- Tests на доступ к private game data только после допустимого перехода.
- Regression tests на старые exercise/evaluator versions.
