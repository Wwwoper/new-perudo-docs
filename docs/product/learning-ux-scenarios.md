# Пользовательские сценарии учебной системы Perudo

Версия: 1.0
Статус: продуктовый контракт сценариев; дополняет, но не заменяет `product-scenarios.md`.

## 1. Назначение

Документ описывает сценарии выбора навыка, начала обучения, диагностики, переключения, смешанной тренировки, разбора ошибок, просмотра прогресса и завершения учебной сессии. Сценарии не предписывают конкретные экраны или технологии.

Существующие PS-01–PS-09 остаются действующими. Здесь добавлены PS-10–PS-17.

## 2. Дополнительные сценарии

### PS-10. Выбор навыка

**Цель:** пользователь понимает, какие навыки доступны, чему они учат и каков его текущий прогресс.

Основной поток:

1. Пользователь открывает обзор навыков.
2. Для каждого S1–S9 отображаются название, краткая цель и индивидуальное состояние прогресса.
3. Рекомендованный следующий шаг визуально различим, но не блокирует остальные навыки.
4. Пользователь выбирает навык и видит доступные режимы.

Критерии приёмки:

- навыки не объединяются в общий уровень пользователя;
- статус и рекомендация различаются;
- выбор другого навыка не сбрасывает незавершённую попытку.

### PS-11. Начало обучения навыку

**Цель:** пользователь получает минимально достаточное введение и может начать упражнение.

Основной поток:

1. Показывается цель навыка простым языком.
2. При необходимости показывается краткое объяснение или разобранный пример.
3. Пользователь начинает первое упражнение.
4. Упражнение генерируется, валидируется и сохраняется до показа.
5. Создаётся попытка только после явного начала.

Критерии приёмки:

- теория не перегружает экран упражнения;
- пользователь понимает, чему учится;
- предварительная генерация не создаёт попытку.

### PS-12. Диагностика навыка

**Цель:** подобрать разумную стартовую сложность без объявления навыка освоенным.

Основной поток:

1. Пользователь выбирает диагностику или принимает предложение системы.
2. Получает несколько заданий, охватывающих разные стороны навыка.
3. Результаты используются для рекомендации стартового уровня и пробелов.
4. Пользователь видит краткий итог и может начать обучение или выбрать другой режим.

Критерии приёмки:

- диагностика не подменяет обычные учебные попытки;
- её результат сам по себе не переводит навык в `MASTERED`;
- пробелы и уверенно выполненные области показываются раздельно.

### PS-13. Переход между навыками

**Цель:** пользователь может свободно переключаться между навыками без потери учебных данных.

Основной поток:

1. Пользователь выбирает другой навык.
2. Незавершённая попытка сохраняет своё состояние.
3. При возвращении пользователь может продолжить ту же попытку, если её статус допускает продолжение.
4. Система может предложить упражнение по предпосылке, но не блокирует переход без продуктовой необходимости.

Критерии приёмки:

- переключение не создаёт новую попытку автоматически;
- прогресс и история навыков независимы;
- переход не меняет результаты уже сохранённых отправок.

### PS-14. Смешанная тренировка

**Цель:** пользователь тренирует несколько ранее изученных навыков в одной сессии.

Основной поток:

1. Пользователь выбирает `MIXED` или принимает рекомендацию.
2. Learning Strategy подбирает сочетание навыков и типов упражнений.
3. Каждое упражнение явно обозначает основной навык-владелец.
4. Результаты и ошибки учитываются по соответствующим навыкам.

Критерии приёмки:

- смешанная сессия не скрывает цель отдельного упражнения;
- неизвестные предпосылки не вводятся незаметно;
- прогресс не сводится к единому баллу смешанной сессии.

### PS-15. Разбор серии ошибок

**Цель:** пользователь понимает повторяющуюся трудность и получает конкретное упражнение для её устранения.

Основной поток:

1. Learning Progress предоставляет статистику ошибок по навыку.
2. Система определяет повторяющийся диагностический признак по прозрачному правилу.
3. Feedback объясняет наблюдаемую проблему без обвиняющих формулировок.
4. Learning Strategy предлагает упражнение по той же учебной цели или её предпосылке.

Критерии приёмки:

- рекомендация опирается на сохранённые ошибки;
- единичная ошибка не называется устойчивой проблемой;
- исходные отправки и результаты не переписываются.

### PS-16. Просмотр прогресса

**Цель:** пользователь понимает текущее состояние каждого навыка и предстоящие повторения.

Основной поток:

1. Пользователь открывает обзор прогресса.
2. Видит статусы S1–S9, недавнюю активность и доступные review tasks.
3. Может перейти к истории попыток конкретного навыка.
4. Может принять рекомендацию, отложить её или выбрать другой навык.

Критерии приёмки:

- отображается прогресс отдельно по навыкам;
- точность первой и итоговой отправки не смешивается;
- подсказки и самостоятельность не скрываются внутри одного accuracy;
- пропуск рекомендации не означает освоение.

### PS-17. Завершение учебной сессии

**Цель:** пользователь получает короткий и полезный итог текущей сессии.

Основной поток:

1. Пользователь завершает сессию или прекращает занятия.
2. Система показывает выполненные упражнения и навыки, которые практиковались.
3. Показываются существенные успехи и одна приоритетная рекомендация, если она есть.
4. Пользователь может продолжить, перейти к другому навыку или закончить.

Критерии приёмки:

- завершение сессии не подменяет завершение/отказ от отдельной попытки;
- итоги строятся по сохранённым фактам;
- не создаётся общий рейтинг пользователя;
- следующий шаг рекомендован, но не обязателен.

## 3. Общие состояния пользовательского процесса

Типовой пользовательский путь:

`выбор навыка → введение/пример (если предусмотрены) → выполнение → отправка → feedback → следующий шаг/исправление → завершение упражнения → разбор → рекомендация`.

Это описание пользовательского процесса и не заменяет жизненный цикл `ExerciseAttempt`: `STARTED`, `IN_PROGRESS`, `COMPLETED`, `ABANDONED`.

Правила:

- исправление возможно только после feedback;
- полный эталон раскрывается только после завершения всего упражнения;
- обязательные шаги определяют возможность завершения;
- optional шаги не блокируют завершение и не уменьшают обязательный балл;
- повторное открытие разбора не изменяет прогресс;
- восстановление использует существующие идентификаторы попытки и отправки;
- один главный призыв к действию должен быть очевиден в каждом состоянии.

## 4. Общий UX-контракт

Сохраняется порядок смысловых зон из `product-scenarios.md`:

1. навык и цель;
2. короткая инструкция;
3. ситуация и необходимые данные;
4. область ответа;
5. результат с коротким выводом;
6. подробное объяснение/подсказка по запросу;
7. следующий шаг.

Desktop и mobile используют одинаковые понятия, правила и последовательность действий; компоновка может адаптироваться к размеру экрана. Цвет не является единственным способом передачи статуса. Подробная теория не должна конкурировать с условием текущего упражнения.
