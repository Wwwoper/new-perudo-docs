# Сценарии UX-проверки MVP

**Статус:** сценарии для будущих модерируемых и технических проверок; сессии не проводились.

## 1. Цель

Проверить, что пользователь может пройти минимальный учебный цикл без подсказок модератора, понимает состояние задания и не раскрывает эталон до завершения. Проверка не подтверждается одним визуальным просмотром скриншотов.

## 2. Сессии

| Session | Участник/контекст | Задание | Критерий успеха |
|---|---|---|---|
| UX-01 | Первый запуск, desktop | создать локальный профиль и начать первое упражнение | пользователь самостоятельно находит основное действие и понимает локальность данных |
| UX-02 | Первый запуск, mobile | пройти короткое S2/S3 упражнение | контент и главное действие доступны без горизонтальной прокрутки |
| UX-03 | Многошаговое упражнение | ответить, ошибиться, исправить после feedback | пользователь понимает, что исправление — отдельная отправка, а эталон ещё скрыт |
| UX-04 | Подсказка | запросить hint и завершить упражнение | hint отделён от ответа; влияние на независимость объяснено |
| UX-05 | Завершение | прочитать feedback и следующий шаг | пользователь может объяснить основную ошибку и выбрать продолжение |
| UX-06 | Восстановление | обновить/закрыть вкладку в активной попытке | сохранённый статус и доступное действие понятны; попытка не дублируется |
| UX-07 | Прогресс | открыть skill progress и review | first/final/assisted/independent evidence не смешаны в одну неясную оценку |
| UX-08 | Keyboard-only | пройти основные действия без мыши | фокус видим, порядок логичен, все элементы достижимы |
| UX-09 | Narrow viewport / zoom | пройти упражнение при увеличении текста | отсутствует потеря критичных действий и информации |

## 3. Протокол наблюдения

Для каждой сессии фиксировать:

- build/version, viewport, browser/device, zoom и input method;
- task start/end и завершено ли без помощи;
- ошибки понимания, возвраты, dead ends и потерянные данные;
- дословные наблюдения отдельно от интерпретаций;
- severity: blocker / major / minor;
- evidence artifact (запись, скриншот, заметка) с согласием участника;
- issue ID, owner, disposition и retest result.

Не записывать чувствительные данные участника. Малое число сессий выявляет usability issues, но не доказывает статистическую доступность для всех пользователей.

## 4. Критерии приёмки

- все критические задачи завершаются без модераторской подсказки;
- нет blocker-дефектов клавиатуры, фокуса, раскрытия эталона или потери попытки;
- ошибки и состояния восстановления имеют понятное сообщение и следующее действие;
- мобильный layout сохраняет содержание и primary action;
- unresolved major issues имеют явное решение владельца продукта до release.

## 5. Статус

Все сессии `NOT_RUN`. Прототип и его скриншоты могут использоваться для подготовки сценариев, но не как доказательство прохождения UX-проверки.
