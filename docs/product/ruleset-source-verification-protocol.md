# Протокол подтверждения источника правил Perudo

**Статус:** процедура проверки; официальная сверка не выполнена.

## 1. Цель

Подтвердить, что `PERUDO_ZYGOMATIC_CLASSIC_V1` и особенно переходы ставок / Palifico соответствуют одной определённой редакции первичного источника. Нельзя собирать итоговые правила из разных редакций, переводов и пересказов без явного решения.

## 2. Иерархия источников

1. Инструкция, приложенная к выбранному физическому изданию Zygomatic, с указанием года/редакции и языка.
2. Официальный файл правил, опубликованный правообладателем/издателем и однозначно относящийся к тому же изданию.
3. Официальная страница издателя — для идентификации издания и версии, но не вместо отсутствующей таблицы правил.
4. Вторичные источники — только как указатель на расхождение, не как основание для закрытия решения.

Если точный первичный документ недоступен, решение остаётся `OPEN`. Нельзя заявлять, что правило «официальное», только потому, что оно распространено в других версиях Perudo.

## 4. Форма извлечения

На каждое правило сохранить:

- source title, publisher, edition/year, language;
- URL или идентификатор физического документа;
- страницу/раздел и дословную короткую формулировку либо точную ссылку на параграф;
- буквальное правило отдельно от проектной интерпретации;
- нормализованную таблицу вход → допустимость → выход;
- ambiguity / translation note;
- reviewer и дату;
- затронутые example IDs и test IDs.

## 5. Правила закрытия

- `APPROVE`: первичный источник однозначен, нормализация независимо проверена, владелец продукта утвердил.
- `CHANGE`: проектный контракт расходится с источником; требуется отдельное изменение Game Domain и регрессионный review зависимых примеров.
- `DEFER`: затронутые сценарии исключены из scored MVP, а границы исключения перечислены.
- `OPEN`: источник или трактовка недостаточны.

Не менять статус решения только ради разблокировки примера. После любого изменения ruleset пересматриваются все примеры и тесты, ссылающиеся на соответствующие rule IDs.
