## 3. Что именно выбрать для PAL-06

Рекомендуемый вариант: после Dudo сначала применить потерю кубика и выбытие, затем вычислить активных игроков; при ровно двух активных следующий раунд NORMAL, при более чем двух и переходе проигравшего с двух кубиков на один — PALIFICO.

Это решение снимает неоднозначность порядка операций и согласуется с формулировкой «когда осталось два игрока». Оно является проектной нормализацией, а не дословной цитатой из инструкции.

## 4. Что именно выбрать для PAL-07

Источник говорит, что игрок, уже объявлявший Palifico, может менять грань. Он не расписывает все количественные случаи. Владелец должен выбрать одну модель:

- `A`: применять к такому игроку общую NORMAL-иерархию повышений (равное количество + более высокая грань; либо большее количество + любая грань), но сохранять PAL подсчёт без джокеров;
- `B`: разрешить менять грань только при одновременном увеличении количества;
- `C`: задать иную формулу и предоставить граничные примеры.

Рекомендация для обсуждения — `A`, поскольку она повторно использует общий механизм повышения, не добавляя отдельную скрытую шкалу. Это рекомендация проекта, не прямое требование источника.

|---|---|
| Decision ID | `BID-01` / `BID-02` / `BID-03` / `BID-04` / `PAL-01` … `PAL-07` |
| Status | `APPROVE` / `CHANGE` / `DEFER` |

| Rationale | Заполнить |
| Reviewer | Заполнить |
| Date | Заполнить |
| Affected examples reviewed | Заполнить после сверки точных example IDs |

`DEFER` требует перечислить исключённые упражнения и сценарии. `CHANGE` требует указать новую формулировку и граничные тесты. `APPROVE` требует подтверждения, что выбранный источник — именно целевая редакция продукта.
