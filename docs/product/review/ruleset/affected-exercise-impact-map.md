# Карта влияния правил ставок и Palifico на S1–S9

**Статус:** impact analysis по текущему документальному каталогу; exercise IDs следует сверить с фактическими карточками перед финальным approval.

## 1. Навыки под влиянием

| Навык | Что меняется | Риск при старом контракте | Обязательное действие |
|---|---|---|---|
| S1 — правила | Допустимость повышения, Paco, запуск/исключение Palifico | Ученик получает неверный нормативный ответ | Обновить правило и негативные примеры |
| S2 — восприятие | Отображение текущего режима и исторического права игрока | Состояние UI может скрыть, почему разрешена смена грани | Явно показывать режим и релевантный статус игрока, не раскрывая private data |
| S3 — подсчёт | NORMAL vs PAL подсчёт Paco | Смешение джокера и обычной единицы | Fixtures отдельно по mode |
| S4 — вероятность | Распределение граней и число hidden dice в PAL | Вероятности неверны при джокерном NORMAL параметре | Проверить все fixtures с `round_mode=PALIFICO` |
| S5 — механика ставок | Весь переходный валидатор | Кандидат ошибочно принят/отклонён | Пересобрать таблицу переходов и boundary tests |
| S6 — история торгов | Восстановление контекста Paco и PAL из последовательности ставок | История может интерпретироваться без режима/версии правил | Включить `round_mode` и ruleset version в контекст |
| S7 — соперники | Наблюдаемые действия оппонента в PAL | Незаконная/разрешённая смена грани может быть ошибочно принята за стиль | Сначала проверять законность хода; не выводить мотивы |
| S8 — решения | Выбор Dudo/повышения при новой legal action set | Оценка решения на недоступном действии | Пересчитать action set на момент решения |
| S9 — стратегия | Планирование вокруг следующего PAL раунда и исключения 2 игроков | План опирается на неверный режим | Пересмотреть только примеры, где PAL влияет на ветвление |

## 2. Группы эталонных примеров для повторного review

| Example family | Приоритет | Причина |
|---|---|---|
| S1/S5 ordinary bid legality | BLOCKER | Нужна полная обычная иерархия ставок |
| S1/S5 Paco transitions | BLOCKER | Новые формулы `ceil(q/2)` и `2p+1` |
| S1/S5 Palifico legal/illegal | BLOCKER | Различие обычного участника и ранее объявлявшего Palifico |
| S3/S4 Palifico count/probability | HIGH | Paco не джокер в PAL |
| S6 bid history involving Paco | HIGH | Нужна корректная интерпретация перехода |
| S7 opponent behavior in PAL | MEDIUM | Сначала legality, затем классификация поведения |
| S8 decision with changed action set | HIGH | Решение оценивается по доступным на тот момент действиям |
| S9 multi-round plan with PAL | HIGH | Режим действует один следующий раунд; исключение двух игроков |

## 3. Минимальный review checklist для каждого затронутого example

- [ ] Зафиксирован `ruleset_id` и `ruleset_version`.
- [ ] Указан `round_mode` в момент каждой ставки и подсчёта.
- [ ] Если есть Paco bid, проверена правильная формула перехода.
- [ ] Если есть Palifico, зафиксированы активные игроки в момент активации.
- [ ] Если разрешена смена грани, показано основание `has_declared_palifico=true`.
- [ ] Публичная часть содержит только доступную игроку информацию.
- [ ] Expected answer, accepted alternatives и evaluator criteria пересчитаны.
- [ ] Negative case доказывает отклонение ближайшего недопустимого варианта.
- [ ] Progress eligibility не засчитывает заблокированный/непроверенный example.

## 4. Ограничение по идентификаторам

Этот документ намеренно ссылается на семейства примеров, а не придумывает конкретные `example_id`. Точные ID должны быть взяты из исходных файлов `docs/learning/examples/*` и внесены в `mvp-example-review-register.md` после их проверки. Если идентификатор отсутствует или не совпадает с содержанием, его нельзя создавать по догадке.
