# Предлагаемые таблицы переходов ставок — Zygomatic 2022

**Статус:** нормализация для решения владельца продукта; не authoritative contract до утверждения.

## 1. Обозначения

- `q` — количество в текущей ставке.
- `f` — грань 2–6 обычной ставки.
- `p` — количество Paco в текущей ставке.
- `ceil(x)` — округление вверх.
- `N` — NORMAL; `P` — PALIFICO.
- `has_declared_palifico` — игрок ранее фактически объявлял Palifico в этой партии.

## 2. NORMAL: старт раунда

| Текущая ставка | Новая ставка | Статус | Основание |
|---|---|---|---|
| отсутствует | `q >= 1`, грань 1–6 | Допустимо при соблюдении общей верхней границы проекта | Источник: стартовый игрок объявляет количество и значение |
| отсутствует | Paco | Запрещено | Z22-PACO-03 |

Для обычной ставки на грань 1 подсчёт остаётся отдельной частью текущего проектного контракта; переходная таблица не должна автоматически трактовать `1` как Paco bid.

## 3. NORMAL: повышение обычной ставки

| Предыдущая ставка | Кандидат | Допустимость по источнику | Формула/проверка |
|---|---|---|---|
| `(q, f)` | `(q, f2)` | Да, если грань повышена | `f2 > f` |
| `(q, f)` | `(q2, f2)` | Да, если количество увеличено; грань может быть любой допустимой | `q2 > q` |
| `(q, f)` | `p Paco` | Да, отдельный переход | `p >= ceil(q / 2)` |
| `(q, f)` | `(q2, f2)` при `q2 < q` | Нет | Количество не увеличено и грань не сохранена/повышена по отдельному правилу |
| `(q, f)` | `(q, f2)` при `f2 <= f` | Нет | Грань не увеличена |

**Важно:** правила проекта о запрете ставки выше общего числа активных кубиков накладываются как дополнительный верхний предел. Это отдельное проектное ограничение, а не переходная формула из источника.

## 4. NORMAL: повышение после Paco

| Предыдущая ставка | Кандидат | Допустимость по источнику | Формула/проверка |
|---|---|---|---|
| `p Paco` | `p2 Paco` | Да, если увеличено количество | `p2 > p` |
| `p Paco` | `(q, f)` | Да, если выбранная грань не Paco | `q >= 2 * p + 1` |
| `p Paco` | `p2 Paco`, `p2 <= p` | Нет | Количество Paco должно увеличиться |
| `p Paco` | `(q, f)` при `q < 2p + 1` | Нет | Не выполнена нижняя граница |

## 5. PALIFICO: повышение

| Игрок, размещающий ставку | Кандидат относительно предыдущей ставки | Источник подтверждает | Требуется решение/тест |
|---|---|---|---|
| `has_declared_palifico = false` | Та же грань, большее количество | Допустимый путь, поскольку грань менять нельзя | Утвердить применение общего правила увеличения количества |
| `has_declared_palifico = false` | Другая грань | Запрещено | Позитивный/негативный тест |
| `has_declared_palifico = true` | Другая грань | Право менять грань подтверждено | Утвердить количественное условие: `q_new > q_old` или допустимость равного количества с более высокой гранью |
| Любой игрок | Paco как стартовая ставка | Допускается только в Palifico | Проверить совместимость с фиксированной гранью и правом менять грань |

Нельзя утверждать полную таблицу Palifico только на основании фразы о праве менять грань. Строки, для которых источник не задаёт количественные границы, должны получить owner decision и явную пометку `PROJECT_INTERPRETATION`.

## 6. Двухигровое исключение и активация

Источник подтверждает два факта: Palifico инициируется после потери игроком четвёртого кубика и правила Palifico не применяются, когда осталось два игрока. Для реализации требуется выбрать точку измерения числа активных игроков.

Рекомендуемая нормализация для утверждения:

1. Разрешить Dudo атомарно и определить игрока, потерявшего кубик.
2. Обновить количество кубиков и исключить выбывшего игрока из активных.
3. Перед созданием следующего раунда вычислить число активных игроков.
4. Если активных игроков ровно два — следующий раунд NORMAL.
5. Если активных игроков больше двух и проигравший перешёл с двух кубиков на один — следующий раунд PALIFICO, проигравший объявляет Palifico и начинает раунд.
6. Иначе следующий раунд NORMAL.

Пункты 3–5 — предлагаемая проектная нормализация, а не дословная последовательность из инструкции. Владелец продукта должен утвердить её.

## 7. Неизменяемые правила, не затронутые этой таблицей

- Calza отключено в MVP.
- В NORMAL Paco учитываются как джокеры при проверке ставки на грань 2–6.
- В PALIFICO Paco не являются джокерами.
- Только раунд непосредственно после соответствующей потери кубика является Palifico.
- `has_declared_palifico` сохраняется после фактического объявления до конца партии — если это утверждается как доменная модель.
