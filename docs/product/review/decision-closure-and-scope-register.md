# Реестр закрытия продуктовых решений и границ MVP

**Статус:** рабочий реестр; не утверждает решения за владельца продукта.

## 1. Принцип

Этот документ сводит открытые решения из Game Domain, Product Owner Decision Packet, learning policy и S1–S9 audit. Он не меняет authoritative contracts. Решение считается закрытым только после записи `APPROVE`, `CHANGE` или `DEFER`, reviewer, даты, основания и обновления целевого нормативного документа.

## 2. Блокирующие игровые решения

| Decision | Требуемое подтверждение | Зависимые навыки | Release treatment до approval |
|---|---|---|---|
| BID-01 | Полная таблица обычных повышений ставки: количество/грань, все допустимые и недопустимые переходы | S1, S5, S8, S9 | Блокировать все scored cases, где переход не задан текущим authoritative contract |
| BID-02 | Переходы на единицы и с единиц обратно, включая границы количества | S1, S5, S8 | Блокировать соответствующие варианты |
| PAL-01 | Таблица допустимых переходов в Palifico | S1, S5, S9 | Блокировать варианты, где эталон зависит от перехода |
| PAL-02 | Двухигровое исключение: trigger, момент, длительность и последствия | S1, S5, S9 | Не оценивать исключение до решения |
| PAL-03 | `has_declared_palifico`: точный момент установления, persistence и взаимодействие с текущим режимом | S1, S5, S9 | Не оценивать неоднозначные комбинации |
| PAL-04 | Точка проверки числа активных игроков и границы 2/3+ | S1, S5, S9 | Использовать только прямо утверждённые случаи |

Текущие договорённости о составе игры, подсчёте, выбытии, атомарности Dudo и жизненном цикле раунда остаются применимыми в пределах уже записанных контрактов. Этот реестр не расширяет их.

## 3. Learning policy decisions

| Decision | Предложение текущей документации | Что требуется до release |
|---|---|---|
| EVAL-01 | Атомарные `PASS/FAIL/NOT_APPLICABLE/NOT_EVALUATED` и частичная оценка полей | Owner approval рубрики и accepted alternatives |
| PROG-01 | 3 независимых успешных первых отправки на 3 разных экземплярах в 2 сессиях | Подтвердить порог или заменить; проверить критерии по каждому навыку |
| PROG-02 | Не менее 2 существенно разных вариантов, когда они доступны | Утвердить поведение при отсутствии разнообразия |
| PROG-03 | 2 независимых успешных review instances для восстановления mastery | Утвердить и проверить переходы статусов |
| PROG-04 | Интервалы 1/3/7/14/30 дней — калибровочная гипотеза | Утвердить стартовую политику и не называть её оптимальной |
| PROG-05 | Anchor time, календарная интерпретация и grace period открыты | Принять явное решение о времени и overdue |
| PROG-06 | Изменение порогов prospectively или явная versioned reevaluation | Утвердить миграцию исторических evidence |
| LS-01 | `due review → remediation → prerequisite → current skill → next skill → learner choice` | Подтвердить приоритеты и no-eligible state |
| LS-02 | Prerequisites направляют, но не блокируют навигацию | Подтвердить UX поведения |
| LS-03 | Рекомендация не запускает упражнение автоматически и не удаляет незавершённую попытку | Подтвердить сценарии выбора/возврата |

## 4. Решения по S7–S9

| Decision | Рекомендуемая политика | Что не следует делать до approval |
|---|---|---|
| S7-01 | Качественные evidence bands; выводы о мотивах — только гипотезы | Не вводить универсальный числовой минимум наблюдений и психологические ярлыки |
| S8-01 | Цель явно задана в каждом упражнении; несколько вариантов могут быть допустимы | Не задавать глобальную функцию полезности и не оценивать по случайному исходу |
| S9-01 | План содержит цель, предпосылки, условную ветвь, наблюдаемый триггер пересмотра и не обещает случайный исход | Не делать все пять пунктов обязательными для всех уровней без решения владельца |

## 5. Пороги и параметры прототипа

| Параметр | Наблюдаемое значение в `perudo_trainer.html` | Статус в продукте |
|---|---:|---|
| Порог «верю / не верю» | 40% | Только конвенция конкретного упражнения; не game rule |
| Порог максимальной заявки | 55% | Только конвенция конкретного упражнения; не «безопасная» гарантия |
| Порог быстрой прикидки | 6 неизвестных кубиков | Локальная граница приближённого метода; требует проверки калибровки |
| Вероятность для обычной грани | 1/3 | Соответствует текущему записанному NORMAL контракту при применимых правилах |
| Вероятность для единиц | 1/6 | Соответствует текущему записанному NORMAL контракту при применимых правилах |

Совпадение параметра прототипа с контрактом не означает, что весь алгоритм или учебный эталон проверен.

## 7. Итоговый принцип scope

MVP можно сузить, исключив спорные сценарии. Нельзя сохранять сценарий в scored scope и одновременно оставлять его ключевое правило неутверждённым. Нельзя считать документальный план тестирования фактическим доказательством прохождения тестов.
