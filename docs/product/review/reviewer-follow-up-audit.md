## 3. Архитектурное решение: browser runtime

Текущий product baseline требует browser-only local-first web app и offline после первого успешного открытия. Физический runtime для доменной логики не выбран. Не следует выводить из этого решения, что Python обязательно должен исполняться в браузере.

Подготовлен отдельный ADR-013 со статусом `PROPOSED / DECISION OPEN`. До принятия решения нельзя объявлять Python/WASM или TypeScript выбранным стеком.

## 4. Владелец, reviewer и даты

Имена и даты не заполняются предположениями. Минимальный набор ролей для закрытия:

- Product owner — scope, продуктовые интерпретации и принятие остаточных рисков;
- Rules reviewer — независимая проверка BID/PAL и ruleset fixtures;
- Learning reviewer — exercise fixtures, rubric, mastery/review policy;
- Technical reviewer — runtime ADR, storage/offline и browser support matrix;
- UX reviewer — предупреждение TRUSTED_LOCAL, сценарии и accessibility.

Каждое назначение должно содержать конкретное лицо, дату решения/срок и ссылку на evidence. До назначения соответствующий gate остаётся OPEN/NOT_VERIFIED.

## 5. Порядок закрытия

1. Применить этот документационный cleanup и исправление ruleset ID.
2. Получить решение ADR-013, не смешивая его с выбором backend или инфраструктуры, которые не входят в текущий baseline.
3. Сверить PS-01–PS-17 по трассировке во всех acceptance-артефактах.
4. Составить crosswalk BID/PAL ID и проверить единственный источник истины.
5. Утвердить границу scored MVP fixtures; `READY_FOR_REVIEW` не означает `APPROVED`.
6. Назначить владельцев и reviewers, закрывать H-02/H-04/H-05/H-10 по evidence.
7. Только после реализации выполнить H-06/H-07/H-08 и release validation.
