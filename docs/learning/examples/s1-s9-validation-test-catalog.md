# Каталог проверок эталонных примеров S1–S9

**Статус:** план проверок для будущей реализации и ручного review; тесты не запускались.

## 1. Назначение

Каталог превращает обязательные проверки из `mvp-example-review-register.md` и `cross-document-consistency-matrix.md` в проверяемые сценарии. Он не утверждает сами примеры и не заменяет записи reviewer.

## 2. Каталог по навыкам

| Skill | Test family | Positive case | Negative / boundary case | Required assertion |
|---|---|---|---|---|
| S1 | Rule consequence | верный и неверный Dudo | игрок с 1 кубиком теряет последний | проигравший и переход состояния соответствуют контракту |
| S2 | Perception | публичные факты корректно извлечены | скрытые значения отсутствуют в payload | никакое скрытое значение нельзя восстановить из learner DTO |
| S3 | Counting | NORMAL и PALIFICO подсчёт | единицы ошибочно добавлены как джокеры в Palifico | `own_matches` и `required_matches` точны |
| S4 | Probability | exact / at-least | `k=0`, `k>n`, `n=0` | точная дробь совпадает с независимым вектором |
| S5 | Bid mechanics | ставка в пределах явно разрешённого правила | превышение активных кубиков; неизвестный переход | validator не меняет состояние при отказе |
| S6 | History | последовательность `BID_PLACED` и `TURN_ADVANCED` | отсутствующее или переставленное событие | вывод ограничен доступным журналом |
| S7 | Opponent analysis | наблюдение и гипотеза разделены | малый/несопоставимый набор наблюдений | факт не превращается в утверждение о мотиве |
| S8 | Decision quality | цель и допустимые действия заданы | одинаковый исход при разном качестве решения | оценка использует только decision-time evidence |
| S9 | Match planning | план содержит условную ветвь | изменение состояния требует пересмотра | trigger наблюдаем; исход не гарантируется |

## 3. Сквозные проверки

| Test ID | Сценарий | Проверяемая граница |
|---|---|---|
| E2E-01 | S2 public view → S3 count → S4 probability | закрытые значения не проходят между модулями |
| E2E-02 | S5 legality → S6 history reconstruction | legality и reconstruction не смешивают обязанности |
| E2E-03 | S6 observations → S7 hypothesis → S8 decision | сила evidence и доступность в момент решения сохранены |
| E2E-04 | S8 decision → S9 match plan | единичное решение не подменяет долгосрочную стратегию |
| E2E-05 | multi-step exercise → submissions → feedback → progress | эталон скрыт до завершения; first/final/independent различаются |
| E2E-06 | progress facts → strategy recommendation | стратегия не изменяет исторические evidence |

## 4. Обязательные свойства

1. Один и тот же immutable exercise instance всегда имеет один и тот же expected answer при фиксированных версиях ruleset/evaluator.
2. Изменение evaluator не переписывает исторические submission records.
3. Optional criteria не изменяют обязательный итоговый результат.
4. Подсказка фиксируется отдельно и не превращается автоматически в ошибку.
5. Вторичная skill attribution не дублирует primary evidence без отдельного критерия.
6. Невалидный domain command не создаёт частичное изменение состояния.
7. Повтор `command_id` с тем же payload идемпотентен; с другим payload конфликтует.

## 5. Статус исполнения

Все строки этого документа имеют статус `PLANNED`. Для перевода в `EXECUTED` нужны ссылка на реализационный тест, версия кода, дата запуска и результат. Не заменять этот статус словом «проверено» на основании наличия спецификации.
