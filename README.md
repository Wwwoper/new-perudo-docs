# Perudo — документационная основа

Репозиторий содержит требования, нормативные предметные контракты, проектные решения и статусные материалы для нового приложения-тренажёра Perudo. Документация не является доказательством существующей реализации.

## С чего начать

1. [Финальный MVP implementation handoff](docs/product/final-mvp-implementation-handoff.md) — актуальная сводная точка входа для реализации и границ MVP.
2. [Implementation handoff readiness](docs/product/implementation-handoff-readiness.md) — состояние gates и sign-off; значения `NOT_VERIFIED`, `PARTIAL` и `OPEN` не трактовать как PASS.
3. [Реестр открытых действий после аудита](docs/product/review/reviewer-follow-up-audit.md) — подтверждённые несоответствия, неподтверждённые замечания и критерии закрытия.
4. [Реестр решений владельца](docs/product/review/decisions/implementation-decision-register.md) — решения, которые нельзя принимать молча.
5. [Архитектурный обзор](docs/architecture/README.md)
6. [Нормативные контракты](docs/contracts/README.md)
7. [Игровая модель](docs/game-domain/README.md)
8. [Учебная система](docs/learning/README.md)
9. [UX и визуальная модель](docs/ux/README.md)

## Исторические документы

`docs/project-status.md`, `docs/open-questions.md` и `docs/roadmap.md` сохранены для истории консолидации. Их исходные статусы и утверждения о Python-пакетах, незавершённых навыках и открытых правилах не являются текущим baseline. Для текущего состояния используйте документы из пунктов 1–4 выше и нормативные контракты.

Документация фиксирует ожидаемое поведение и принятые решения, но не утверждает готовую реализацию, прохождение тестов или разрешение на релиз.
